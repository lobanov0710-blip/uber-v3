## Подготовлен локальный инструмент

`python3 tools/vehicle_readiness_inventory.py /protected/local-snapshot.sqlite`

Только закрытый самодостаточный локальный SQLite snapshot с базовыми таблицами
Driver/vehicles/availability/assignments; поддерживается схема до классификатора
и последовательно добавленные слои 0019–0024. Отсутствующий слой отмечается
в `schemaCapabilities`, отсутствие части уже существующего слоя — ошибка;
никаких Cloudflare/Firebase API, авторизации, экспорта или подключения к D1.
Получение реального snapshot в утверждённой защищённой среде — отдельный шаг.
В этой работе использованы только синтетические SQLite файлы.
Не загружать snapshot в чат, Git или CI artifacts. Счётчики также предназначены
для закрытого проектного рассмотрения, а не автоматической публикации.

URI `mode=ro&immutable=1`, `query_only`, запрет SQL mutation/ATTACH/extension functions,
фиксированный запрос и одна read transaction. Лимиты: busy timeout 5 секунд,
query deadline 10 секунд. Несовместимая/недоступная база приводит к безопасному
отказу без raw SQL, пути, provider errors и traceback. JSON создаётся лишь после
успешного завершения чтения; ошибка не превращается в нулевые счётчики.
Рабочую изменяемую базу передавать нельзя: нужен заранее завершённый backup.
WAL-mode и наличие -wal/-shm/-journal отклоняются, чтобы immutable reader
не пропустил незавершённые данные и не создал sidecar-файлы. Сам инструмент
не преобразует и не копирует базы.

18 метрик: количество автомобилей, пропуски года/цвета/binding, несовпадение
параметров pin, binding без правила, отсутствие исторической/текущей проверки,
текущие candidate/manual_review/excluded, заявленный BEV, approved без совпадающего
candidate, online drivers и такие online без candidate, active assignments,
active holds и active assignments без candidate. Категории пересекаются и
не складываются в число проблемных автомобилей. Assignments считаются по state
и revoked_at; это не определение активной поездки по статусу заказа.

`current_candidate` — только наличие metadata текущей trusted view, не полный
admission guard: документы водителя, фото, другие условия допуска и назначение
также проверяются runtime. `admissionEvaluated=false`, `activationAuthorized=false`
устанавливаются всегда. Отсутствие года, pin или evidence не исправляется чтением.
View учитывает срок evidence на момент SQL statement; report timestamp отмечает
окончание наблюдения. Нужен новый отчёт перед любыми будущими решениями.

До классификатора `schemaCapabilities` сообщает отсутствие полей года/силовой
установки, bindings/trust/holds. Отсутствующий год остаётся неизвестным (все такие
строки входят в missing_year); отсутствие хранения trust не создаёт кандидатов.
Ноль declared BEV при отсутствии поля не доказывает отсутствие электромобилей,
ноль holds при отсутствии слоя не подтверждает исправность поездок. Счётчики
показывают только записанные сведения вместе с возможностями схемы.
