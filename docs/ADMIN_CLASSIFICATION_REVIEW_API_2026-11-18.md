# G2: public review и доверенное чтение классификации

Продолжение утверждённого контракта в отдельной ветке `arch/g2-admin-classification-review` от проверенного PR №42. Новые бизнес-правила, grants, миграции и зависимости не вводятся.

POST `/v1/admin/vehicles/{vehicleId}/classification/review` использует проверенный atomic recorder: bounded JSON 16KiB, точные поля, обязательный Idempotency-Key, vehicle/input/rule CAS, фактические staff/session/OWNER MFA и проверенные STS. Standard требует существующее vehicles.verify; exception доступен только OWNER с действующим MFA. Сервер вычисляет класс, не принимает actor/роль/класс/verification flags. Исправление марки ограничено утверждённым перечнем. В ответе только утверждённый итог и общий requestId; внутренний assessmentId остаётся в истории. Candidate не выставляет approved или class-проекцию и не включает линию; отдельное итоговое одобрение сохраняется. При коррекции действуют off_line/hold и ручное действие диспетчера, автоматической замены нет.

GET `/v1/admin/vehicles/{vehicleId}/classification` возвращает прежние declaredParameters/pin и теперь читает verifiedParameters/classification/evidence из актуальной trusted view. Просроченный или навсегда инвалидированный proof не возвращается как текущая проверка; immutable история сохраняется. Conditions относятся к точной версии актуальной проверки, включая модель-основание исключения; без текущего proof показываются условия закреплённого правила. Реальная модель не подменяется моделью-основанием. BEV/год/условия/кузов решает существующий серверный evaluator.

История содержит только утверждённые assessmentId/vehicleRevision/ruleVersion/outcome/createdAt, по 50 результатов от новых к старым. Opaque historyCursor содержит hash scope автомобиля/actor и generation (vehicle revision + max sequence); без контактов, номера, VIN, текста причины или документов. Чужой scope и malformed cursor дают 400; изменившаяся generation — 409. Права и фактические session/MFA проверяются снова в одной audited D1 batch для каждой страницы. Новое правило без изменения автомобиля не меняет его pin. Исторический candidate не означает текущий допуск.

Ни GET, ни POST не возвращают object keys, URL, document content, VIN, номер, контакты или свободный reason. Evidence — только ID/revision; отдельные разрешения на чувствительные материалы не выдаются. Read/write audit failure откатывает транзакцию и даёт безопасный 500 без SQL/provider text. OWNER-only phone allowlist не расширен.
