# Закрытая инвентаризация STAGING — Windows

Владелец утвердил вариант A 2026-11-19. Пакет получает метаданные и 18 агрегатов
только из `transfer-servis52-staging` / `66474481-a123-47f9-81b4-12af7565ec8d`.
Он сохраняет закрытый JSON. Существующие OWNER, пароль/TOTP и автомобили
этим инструментом не изменяются. Полная база/документы не выгружаются.

## Подготовка один раз

1. Проверьте SHA256 полученного ZIP по выданной квитанции:
   `Get-FileHash .\vehicle-inventory-readonly.zip -Algorithm SHA256`.
2. Распакуйте **в новую отдельную папку**. Файлы старого `owner-phone-setup`
   сюда не копируйте, файлы этого пакета поверх старого не заменяйте.
3. Нужны Node.js 24 LTS и npm 11.9.0. Версии: `node --version`, `npm --version`.
   При другом npm: `npm install --global npm@11.9.0 --ignore-scripts`.
4. Откройте обычный приватный PowerShell в `vehicle-inventory-readonly`:

```powershell
npm ci --ignore-scripts
node .\scripts\vehicleInventoryRead.mjs init
node .\scripts\vehicleInventoryRead.mjs read
```

`init` просит только Cloudflare Account ID: 32 строчные шестнадцатеричные буквы/
цифры из вашего Dashboard, не API-токен. Уже существующий корректный config
используется без замены и без повторного ввода. Чужой target/неверный config
приводит к остановке. Не редактируйте его для другой базы.

Используется действующая приватная Cloudflare-авторизация владельца, настроенная
для OWNER setup. Новый OAuth login/новые токены или расширение прав этим порядком
не запрашиваются. Если авторизации/прав нет или произошла ошибка, остановитесь
и сообщите только имя шага. Коды входа/токены/пароли в чат не передавайте. Не запускайте в CI,
PowerShell transcript, записи экрана или с перенаправлением вывода.

## Приватное чтение

CLI проверяет source/query hashes и точный target. Выбирает один из пяти
проверенных профилей по миграциям/таблицам/столбцам. Неизвестная или частичная
схема — отказ, а не повод применять миграции. После показа профиля и public
query hash запросит точную фразу:

```text
READ STAGING VEHICLE METRICS
```

После подтверждения создаётся новая папка в вашем профиле Windows, с доступом
только вашей учётной записи и SYSTEM. Выполняется один фиксированный aggregate
SELECT; повторная проверка метаданных отклоняет изменившуюся схему. Ошибки,
timeout и неполный JSON не превращаются в нулевые результаты.

Успех — `READ_ONLY_COMPLETE`, затем имя папки под `%USERPROFILE%`:

- `metrics.private.json` — 18 чисел, возможности схемы, источник и окно времени.
  Храните у себя, вне Git/общих облачных папок. В чат/CI/GitHub не отправляйте.
- `receipt.public.json` — квитанция без чисел, личных данных, credentials,
  provider output и хеша закрытого отчёта. **Для проверки отправляйте только её.**

Каждый запуск создаёт отдельную папку, предыдущие отчёты не перезаписываются.
При обработанной ошибке новый незавершённый результат удаляется; прежняя успешная квитанция
не является результатом нового запуска. `PRIVATE_OUTPUT_CLEANUP_REQUIRED`
означает остановку для отдельного разбора удаления локального незавершённого файла.
После аварийного завершения процесса закрытый незавершённый файл может остаться
в новой защищённой папке; отсутствие новой `receipt.public.json` не считается успехом.

## Рассмотрение результата

Счётчики пересекаются: их нельзя складывать в число проблемных машин.
Отсутствие поля powertrain не означает отсутствие электромобилей; отсутствие
holds слоя не доказывает исправность поездок. Orphan/NULL ссылки учитываются
как отсутствие совпадающего candidate; operational counters могут превышать
число записанных автомобилей. Candidate не означает допуск на линию.

`activationAuthorized=false`, `admissionEvaluated=false` остаются всегда.
Закрытые числа нужны владельцу для отдельного плана обработки пробелов.
Публичная квитанция подтверждает выполненное чтение/формат, но не рассмотрение
содержимого закрытого отчёта разработчиком. G1 остаётся на паузе.
