# TOTP в двух приложениях — 2026-11-15

**Transfer Admin и приложение-аутентификатор — два разных приложения.**
Буквенный ключ показывается в Admin, вводится в аутентификатор. Из
аутентификатора обратно в Admin вводятся только шесть цифр.

| Где поле | Что вводить |
| --- | --- |
| Transfer Admin: Код подключения | Новый bootstrap из приватного PowerShell |
| Аутентификатор: Ключ / Ваш ключ | Новый буквенный Base32 key, показанный в Admin |
| Transfer Admin: Код аутентификатора | 6 цифр, которые показывает аутентификатор |

Цифровая клавиатура в последнем поле правильная. Это поле не принимает
секретный буквенный ключ и не требует переключения на буквы.

## Текущее незавершённое подключение

Владелец подтвердил, что ещё не вводил успешный 6-значный код/не получил recovery.
Потенциальный key отправлен в чат; его не используем и не повторяем в документах.
Для нового подключения в рамках уже утверждённого STAGING этапа:

1. Сначала установите/откройте отдельный TOTP аутентификатор, например официальный
   Google Authenticator из Google Play. Подготовьте manual key setup, прежде чем
   начинать новый короткий enrollment в Admin.
2. В Admin нажмите «Выйти», если кнопка видна. В исправленной папке PowerShell
   с source a7ed6128 выполните `node .\scripts\adminOwnerPhoneSetup.mjs owner`.
   Подтвердите точную фразу для **существующего OWNER**. Новую account/пароль/
   JWT или MFA encryption key не создавайте. При уже enrolled factor CLI
   остановится, reset не выполнять.
3. Войдите в Admin прежними login/password и введите новый bootstrap из терминала.
   Новый pending key покажется на экране. Старые challenge/enrollment/bootstrap
   после successful reissue не действуют; это не сброс подключённого фактора.
4. Приватно перепишите новый key перед переключением приложений, например на
   бумагу, которую затем безопасно уберите/уничтожьте. Admin очищает seed в фоне,
   IDs удерживаются в RAM только до исходного 5-минутного срока. Общий clipboard,
   чат/скриншоты или отключение FLAG_SECURE не используются.
5. В Google Authenticator: «+» → «Ввести ключ настройки». Название записи можно
   выбрать, например Transfer Admin STAGING; в поле «Ключ» введите новый key
   из Admin, тип — «По времени». Base32 key использует латинские A–Z и цифры
   2–7; переписывайте точно. В другом TOTP приложении выберите аналогичный
   ручной ввод с SHA-1, 6 digits, 30 seconds.
6. Аутентификатор покажет 6 цифр. Вернитесь в Admin до исходного срока попытки
   и введите **эти цифры** в «Код аутентификатора», нажмите подтверждение.
7. Сохраните выданные recovery-коды приватно до ухода в фон: они показываются
   один раз. Затем выполните новый вход паролем и новым TOTP, дождитесь следующего
   30-секундного кода после enrollment.

Если исходные 5 минут истекли, повторение переключений срок не продлевает.
Используйте новый protected setup до подключения фактора, не обходите TTL/лимиты.
Если CLI обнаружил уже подключённый factor или действие завершилось неоднозначно,
остановитесь и выполните read-only plan для разбора; reset отдельно не утверждён.
Пароли, seed, bootstrap, OTP и recovery-коды не отправляйте в чат.
