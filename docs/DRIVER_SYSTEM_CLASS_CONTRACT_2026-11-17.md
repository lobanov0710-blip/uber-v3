# Driver: запись автомобиля без выбора класса

Объём: следующий зависимый срез G2 после immutable version store и миграции0020.
Основание — утверждённые владельцем правила системного класса и изменения
марки/модели/года, зафиксированные в Android docs PR13. Это не новый допуск
и не завершение всей классификации.

POST /v1/driver/vehicles принимает modelYear как целое JSON-число1..9999;
это граница представления года, не правило допуска по году. vehicleClass,
powertrain и признаки проверки документов от Driver запрещены. Новый автомобиль
имеет draft и vehicleClass:null. PATCH принимает modelYear и expectedRevision;
для старой записи без года допускается sparse PATCH без нового modelYear.
Ни один из этих путей не назначает доверенный класс.

При фактическом изменении make/model/modelYear сравнение revision защищает
согласованную запись: класс очищается, approved/photo_check_required переходит
в pending_review, доступность активного автомобиля становится off_line.
Изменение, минимальное событие аудита и off_line выполняются одной D1 batch;
ошибка аудита откатывает всё. Проверка активного driver включена в SQL записи.
В событие не попадают VIN, номер, документы или тело запроса.

PATCH возвращает requiresDispatcherReassignment:true при оставшемся активном
назначении на этот автомобиль. Назначение сохраняется для ручного разбора:
автоматического подбора, отмены или фиктивного завершения заказа нет.
Фазовый переход и оба пути завершения заказа требуют допустимого состояния
автомобиля и ненулевого класса, в том числе в SQL защиты от гонки.
Клиент должен показать безопасную остановку и обращение к диспетчеру.
При потере ответа изменение нельзя автоматически повторять: итог неизвестен.

Проверки: восемь новых actual SQLite/HTTP cases, существующая регистрация,
phase/terminal regressions; полный npm test и девятый native D1 workflow в CI.
Точные source/run/results приводятся в отдельном verification receipt после CI.
Нет реальных персональных данных или удалённых привязок в новых fixtures.

Осталось: trusted Admin проверка года/исполнения по документам, выбор актуального
правила и snapshot при классификации, запрет линии для всех legacy записей без
проверенного года, Admin UI изменения правил/исключения, полный dispatcher
handoff уже начавшейся поездки и уведомление пассажира. Текущий reassign для
order taken не доказывает handoff для in_progress. Полный BEV обзор не завершён.
Старые клиенты, посылающие vehicleClass, несовместимы с новым write API;
совместное развёртывание API/нового Driver требует отдельной подготовки.
Нельзя считать этот промежуточный срез готовым к production.

Нет seed, remote migration, deploy/merge или возобновления G1. D4–D7 не изменены.
