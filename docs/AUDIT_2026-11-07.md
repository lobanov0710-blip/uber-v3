  адреса расчёта и URL/body/error в HTTP helper; после исправления проходят.

  SQLite adapter применяет все production migrations, включает foreign keys

  до idempotent replay; смена тела под тем же ключом → conflict.

  Worker bundle сформирован локально, deployment не выполнялся.

- OSV batch для 17 явно выбранных Maven-компонентов после исправления:

## Открытые release blockers и порядок продолжения

1. **Высокий:** terminal API `POST /orders/{id}/status` для done/canceled ещё
   не требует expectedRevision/Idempotency-Key и не пишет полный audit D3.
   Нужны единая транзакция terminal state + assignment + audit + idempotency,
   негативные гонки cancel/done/reassign и обновление клиентского контракта.
2. **Высокий:** полный допуск к on_line/новым назначениям ещё не включает
   месячный фотоконтроль, 24-часовой grace period и внеплановый запрет;
   проверка конфликтующих назначений также не завершена.
   Проверки должны жить в SQL/сервере, не только в UI или рекомендациях.
3. **Совместимость:** текущий Android всё ещё ожидает legacy new_order,
   предлагает self-take/start и не реализует новый assigned-only/phase flow,
   Phone Auth/App Check и /v1-контракты. Backend уже запрещает обходы.
   Эти ветки нельзя выпускать как согласованный комплект до миграции клиента.
4. **Admin:** отдельный Android-клиент пока отсутствует. Утверждённый D1
   позволяет его реализацию с изолированными app data/Keystore/session context.
5. **Инфраструктура:** Android SDK отсутствует, Firebase-конфигурация не создана,
   Google/R2 credentials в среде не подключены. Последняя полноценная попытка
   Android Gradle checks завершилась SDK location not found.
   Поддельные Firebase-конфиги и выключение обязательных проверок не использовались.
6. **Отдельные решения владельца:** D4 liveness/face, D5 обработка/хранение
   чувствительных данных, D6 ranking/timeouts, D7 GPS не утверждены.
   Доступ к verified и реальный сбор биометрии/запись звонков не имитируются.
7. **До merge/release:** реальные D1/Miniflare concurrency contracts,
   Firebase/App Check и R2 E2E, instrumentation/permissions/backup/screenshots,
   инвентаризация бинарного release APK/SBOM и подпись release APK.

Следующий согласованный D3-подэтап: terminal mutations с revision/idempotency/audit,
затем серверный фотоконтроль и согласование Android с /v1 assignment flow.
Исправления этого аудита не являются разрешением на merge/deploy и не означают
готовность системы к production или отсутствие неизвестных уязвимостей.
