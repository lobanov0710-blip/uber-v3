# G2: единый контроль доверенного допуска

Основание: утверждённый classification contract и журнал PR41. Отдельная ветка arch/g2-vehicle-admission-guard от проверенного PR41. Здесь завершается общий backend assessment guard; public classification POST/GET/history и Admin UI по-прежнему отдельные следующие части.

## Одна серверная проверка

trustedVehicleGuard формирует фиксированный SQL с только внутренними alias/placeholder, без пользовательских SQL-фрагментов. Он требует vehicle_current_trusted_assessments: последняя immutable assessment, последний input binding, фактические параметры, verified matching STS revisions/ownership/type и отсутствие immutable invalidation. Outcome только candidate, class совпадает с текущей системной проекцией. Color обязателен без blank/control. Legacy vehicles.class/status,0019 candidate или флаг powertrainVerified недостаточны. При отдельном final approved guard используется без сравнения прежней проекции, потому что class сервер берёт из проверенного candidate в этом же UPDATE; остальные предпосылки те же.

Документы дополнительно проверяются относительно MAX(server operation time, actual SQLite UTC now). Старый timestamp операции не продлевает уже истёкший документ; задержка после service precheck не позволяет провести запись после expiry. Строгая граница <=expiry закрыта. При естественном истечении view/guard отказывают без перезаписи документов/assessment/history или массового изменения статусов. Уже сохранённое поле availability.state не является самостоятельным доказательством допуска. Новой фоновой политики/автопереназначения не вводится.

Проверка применяется в actual SQL mutations on_line, assign, reassign, operational phase, guarded done и legacy done; service/read advisory используют ту же проверку. Старый approved/final registration используют общий helper, сохраняя docs/photos/usage/актуальные grants/session/OWNER MFA. Assignment options показывают eligible=false/vehicle_classification_required, а не предлагают непроверенную машину как допустимую. On_line возвращает422 с тем же reason. Proof/class mismatch, новый manual_review/excluded, потеря выбранных документов и legacy без подтверждённого года закрывают допуск. Гранты/роли не расширены.

Done требует активное назначение этого водителя в in_trip и пригодный автомобиль. Прежний fallback без assignment удалён: у сервера нет автомобиля, подтверждение которого можно проверить. Manual canceled и off_line остаются допустимы при потере допуска. PR41 holds по-прежнему не дают старому назначению ожить после reapproval. Current rule head не используется вместо закреплённой версии: новая публикация, color и unrelated revision не меняют прежний проверенный class/pin.

## Проверки

9 новых реальных SQLite/auth/HTTP scenarios покрывают положительные line/assign/reassign/phase; expiry без row mutation во всех путях; direct SQL repositories после cached advisory; отсутствие assignment; legacy approved без proof/year; forged class/color; новую manual/excluded поверх прежнего candidate;0019 candidate; строгую границу expiry и time-only race между чтением и transaction. Для последнего SQLite clock задаётся тестовой функцией julianday с той же арностью, production clock не меняется. Native workerd/D1 повторяет настоящий HTTP/MFA + immutable review/approved и все позитивные/негативные операции, direct SQL guards, manual cancel/offline. Никаких real Cloudflare requests.

Положительные operational fixtures теперь явно содержат first-save rule/year/color, immutable reviewed assessment, обе STS и audit; они не выдают голый approved за доверие. Helper находится только в tests, требует явную подготовку и не применяется к legacy/negative cases. SQL constraints и actual historical proof сохраняются; Node и native D1 fixture helpers не импортируются product кодом. Проверки числа audit для операций отдельно учитывают помеченные audit_fixture_admission_* из подготовки: реальные action/audit события не фильтруются runtime. Terminal replay/rollback fixtures теперь явно имеют assignment; новый negative scenario проверяет отсутствие assignment. Никаких production backfill/фальшивых yearVerified.
