# Закрытая инвентаризация STAGING: порядок для утверждения

Статус: предложение, удалённое чтение ещё не разрешено и не выполнялось.
Основание: владелец сообщил, что готового SQLite-снимка нет, и поручил подготовить
порядок безопасного получения для утверждения. Это не разрешение на экспорт.

## Предлагаемый результат

Для текущего аудита достаточно **18 агрегированных счётчиков**. Предлагается
посчитать их внутри D1 одним фиксированным SELECT и получить закрытый JSON
на Windows владельца. Это снимок агрегатов, **не SQLite-копия базы**.

| Вариант | Что получает владелец | Решение |
| --- | --- | --- |
| A, рекомендуется | JSON: 18 чисел, возможности схемы, профиль/хеш запроса и окно времени наблюдения | Предлагается к утверждению |
| B | Полный закрытый SQLite backup для уже проверенного offline-инструмента | Отдельный объём экспорта/хранения; пока не предлагается запускать |

Полный backup может включать данные аккаунтов, password verifiers, сессий,
MFA и документов. Для этих счётчиков такие данные выгружать не требуется.
Если нужен именно SQLite backup, сначала отдельно определяются состав,
доступ, зашифрованное хранение, срок и удаление; разрешение A его не включает.

## Точный предел A

- Только `uber-v3-staging`, D1 `transfer-servis52-staging`, ID
  `66474481-a123-47f9-81b4-12af7565ec8d`. Идентификаторы взяты из действующего
  `scripts/lib/adminPhoneSetupPolicy.mjs`; другой target означает остановку.
- Приватный control plane — Windows PowerShell владельца с его Cloudflare-доступом.
  Новые токены, пароли и browser login codes в чат не передаются.
- Сначала только имена миграций, наличие/тип известных таблиц и их столбцы.
  Данные аккаунтов, документов и значения строк на этом этапе не выбираются.
- Затем **один из пяти фиксированных запросов** из
  [manifest](VEHICLE_LEGACY_INVENTORY_READ_PLAN_2026-11-19.json).
  Произвольный SQL, переключение базы и автоматический apply migrations запрещены.
- Единственный результат SELECT — существующие 18 счётчиков. ID, VIN, номера,
  телефоны, ФИО, свободные причины, ссылки/ключи документов, credential verifiers,
  токены и MFA-данные не возвращаются и не сохраняются в выгрузке.
- Нет INSERT/UPDATE/DELETE, DDL, seed/backfill, deploy, изменения статусов,
  OWNER/password/TOTP, прав или allowlist приложения. G1 остаётся на паузе.

## Подготовленные профили

В [папке SQL](proposals/vehicle-inventory-readonly/) сохранены полностью
развёрнутые SELECT, полученные непосредственно из проверенного offline reader
после исправления orphan JOIN. SHA256 каждого запроса — в manifest.
Каждый запрос уже выполнен только на синтетической SQLite-схеме:

| Профиль | Возможности | Проверенный cutoff миграций |
| --- | --- | --- |
| legacy | Нет полей года/powertrain, bindings/trust/holds | 0018 |
| registration | Год и заявленная силовая установка | 0020 |
| bindings | Дополнительно закреплённая версия правила | 0022 |
| trusted | Дополнительно история и текущая trusted view | 0023 |
| holds | Дополнительно assignment holds | 0025 |

Cutoff — версия **синтетической проверки**, а не предположение о live STAGING.
Профиль выбирается по точным возможностям схемы. Частичный слой, неизвестные
столбцы обязательного слоя, несовпадающий target или неподдерживаемая схема
приводят к отказу, а не миграции ради чтения. Метаданные ещё нужно проверить live
после утверждения; список профилей не означает такой проверки.

## Последовательность после утверждения A

1. Подготовить отдельный закреплённый private read-only CLI/bundle для Windows,
   с проверкой target, manifest/query hashes, строгим разбором provider JSON,
   маскированием ошибок и ограничением времени запроса. Сначала синтетические
   CLI/target/ошибочные схемы/отсутствие credentials в выводе; затем выдача пакета.
   Сейчас такого нового remote CLI ещё нет: SQL-файлы — материал для review.
2. Владелец проверяет исходник/хеш пакета, использует свою приватную Cloudflare
   авторизацию. Метаданные читаются только с указанного STAGING target.
3. CLI показывает безопасный план: target, выбранный профиль и public query hash.
   Перед чтением метрик — точная фраза `READ STAGING VEHICLE METRICS`.
4. Выполняется один SELECT. Его исходные таблицы и time-sensitive trusted view
   читаются в одном SQL statement. Ошибка/timeout/неполный ответ не превращаются
   в нулевые значения и не создают успешный отчёт. Provider stderr/SQL response
   не выводятся в общий журнал/чат. Автоматические исправления не выполняются.
5. В приватный каталог владельца вне Git/общих облачных папок сохраняется JSON:
   18 неотрицательных целых, schemaCapabilities, query hash, начало/конец чтения
   по UTC и source provenance. Это окно наблюдения, не обещание точного DB clock.
   Проверяются vehicle partition и границы счётчиков drivers/assignments.
6. Для чата/журнала — отдельная публичная квитанция: action/result, target/profile,
   query/source hashes, успешная проверка формата и сохранение закрытого отчёта.
   В квитанции **нет метрик и хеша закрытого отчёта**, личных данных, credentials
   или provider output. Низкоэнтропийные числовые данные не раскрываются через hash.
7. Владелец рассматривает закрытый отчёт. Дальнейший план обработки пробелов
   готовится отдельно; статус `activationAuthorized=false` и
   `admissionEvaluated=false` сохраняется всегда. Публичная квитанция не означает,
   что содержание закрытого отчёта уже рассмотрено разработчиком.

Счётчики пересекаются. Ссылки на отсутствующие/NULL автомобили теперь входят в
`online_without_matching_candidate`/`active_assignments_without_matching_candidate`;
они не должны выглядеть исправными и могут превышать число записанных авто.
Отсутствие поля powertrain не доказывает отсутствие BEV, отсутствие holds слоя
не доказывает отсутствие проблем поездок. Candidate не равен допуску на линию.

## Что требуется утвердить

Вариант A: подготовить и проверить описанный private CLI, затем разрешить владельцу
чтение метаданных и одного фиксированного aggregate SELECT на точном STAGING target,
с закрытым JSON и публичной квитанцией без чисел. Это разрешение не даёт права
экспорта полной БД, новых учетных записей, remote writes или активации классификатора.
