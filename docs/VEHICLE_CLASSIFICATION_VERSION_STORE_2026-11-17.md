# Хранение версий классификатора — серверный компонент

Владелец определил: изменение правила применяется только к новым регистрациям,
но при изменении марки, модели или года самого автомобиля пересчёт выполняется
по **текущей версии**. Такое изменение требует проверки и исключает допуск на
линию; при начатой поездке остановка безопасная, замену назначает диспетчер.

## Реализованный объём

Миграция0019 добавляет неизменяемые версии правил, указатель текущей версии для
марки/модели и неизменяемый результат классификации для ревизии автомобиля.
Правила и существующие автомобили миграция не изменяет; seed отсутствует.

`captureCurrentVehicleClassification` читает автомобиль и текущее правило,
вызывает классификатор и сохраняет результат с проверкой той же ревизии и
того же текущего правила в SQL INSERT. При гонке возвращается конфликт.
Исторический результат не меняется при обновлении правила; явная новая ревизия
автомобиля получает текущую версию. Нельзя перезаписать результат той же ревизии
или приписать результат модели, отличающейся от записи автомобиля.

Ограничения SQLite запрещают редактирование/удаление истории, дробные годы и
ревизии, несовместимый с правилом candidate и назначение класса BEV.
Неизвестная модель, неподходящий год и неподтверждённая установка сохраняются
для ручной проверки без фиктивного класса; BEV получает excluded. Candidate
не является approved или допуском к заказам.

Это **внутренний репозиторий**, не внешний API: серверный вызывающий код обязан
проверить сессию/права/владение, брать год/подтверждение установки из доверенной
модерации и записывать операционный аудит. Водитель не может подтверждать
установку флагом из запроса. Эти внешние границы и доверенная модерация здесь
не реализованы и не должны подменяться прямым вызовом репозитория из маршрута.
